# 自動演習・採点 PoC メモ

以下はリポジトリ内で議論した「自動演習／自動採点」の PoC 案を短く整理したメモです。
目的は短期間で価値検証できる実装を順に回すことです。

## 背景
- 対象: GeoGebra の `.ggb`（内部は XML/ZIP）を `ggblab` のパーサで解析し、構成要素（点／線／依存関係／式）を抽出する。
- 目的: 学生提出物とリファレンスを比較してスコアと改善フィードバックを自動生成する。

## 高レベル戦略

- ルールベース（軽量）: 重要オブジェクトの存在チェック、距離/角度の許容誤差、幾何的不変量（比・角度）による部分採点。
- 構造類似度（グラフ）: Construction をノード/エッジで表現し、NetworkX 等で部分木マッチや GED（Graph Edit Distance）を使ってスコア化。
- 記号的検証: SymPy を用いた式同値判定（例: 表示式や係数の同値性検査）でセマンティックな等価を判定。
- 学習ベース（将来的）: GNN 等で意味的類似性を学習。まずは小規模データで試す。

## 提案 PoC（短期→中期）

- PoC A — GED ベース（短期、推奨スタート）
  - 目標: `.ggb` をパース→NetworkX グラフ化→簡易 GED を計算して正解に対する類似度スコアを出す。
  - 成果: `examples/poc_ged_grader.ipynb`（リファレンス + 数件の変形サンプル付き）。
  - 利点: 実装コスト低めで構造的差分が見える化できる。

- PoC B — ルール + 座標アライメント（中期）
  - 目標: 重要オブジェクト（対応点）を Procrustes 的に位置合わせし、距離/角度比で厳密採点。欠落・過剰オブジェクトの箇所フィードバックを生成。
  - 成果: スクリプト形式でスコアとヒントを返す CLI/Notebook。

- PoC C — 学習ベース (探索)
  - 目標: 少量のラベル付きペアで GNN を学習し、意味的等価を捕らえる。
  - 成果: 研究的検証ノートブック（精度評価・誤判定解析）。

## 実装上のポイント / ツール

- パーサ: `ggblab_extra` の ConstructionIO / parser を利用してオブジェクト一覧と依存グラフを抽出。
- グラフ処理: `networkx`（同型、GED、部分木マッチング）。単純な GED 実装で十分に有用。
- 数値整合: NumPy / SciPy（Procrustes アライメント、距離計算）。
- 記号検証: `sympy`（式の簡約・同値判定）。

### SymPy の扱い（方針）

- フォーカス: `SymPy.Function` と `lambdify` を中心に据えます。式の同値性検証や数値サンプリングは、まず `lambdify` で数値関数化してサンプル比較を行い（許容誤差を設定）、補助的に `sympy.simplify` / `sympy.together` 等で記号的簡約を試みます。
- 例: 表示式や関数定義が `f(x)=x**2` と `x**2` のように見える場合、`lambdify` による多点サンプリングで等価性を確認してから、必要に応じて `simplify` で補助検証するフローを推奨します。
- SymPy.Geometry: 採用は限定的にします。GeoGebra 固有の構成（依存関係、オブジェクトモデル）は独自パーサで扱い、ジオメトリ表現の高度な操作のために `SymPy.Geometry` に深入りしない方針です。
- 座標変換・多様体: 座標変換や座標系の取り扱いが必要なユースケースでは `sympy.manifolds`（SymPy.Manifold）を優先検討します。一般相対性や複雑なマニフォールド変換が必要な場合は `einsteinpy` の検討を推奨します（依存は重くなるためオプション扱い）。
- 実装メモ: `lambdify` の `modules` に `numpy` を指定して高速数値評価を行い、サンプル点は均等グリッドかランダムサンプリングで多点検証することで誤判定を低減できます。


## 評価指標

- 精度（人が正解と判断した中で自動採点が合っている割合）
- 偽陽性率（誤って合格させた割合）
- フィードバック有用度（人による主観評価）
- 実行時間（1 件あたり）とスループット（バッチ処理）

## データ準備案

- 最初は手動で 5–30 ペアのリファレンス／誤答サンプルを用意して、PoC の出力（スコア＋フィードバック）を人が評価する。
- `ConstructionIO.save_dataframe` で特徴量を Parquet/JSON に落とし、後で学習/分析に使う。

## 短期の実行プラン（推奨）

1. PoC A ノートブックを `examples/poc_ged_grader.ipynb` として実装する（NetworkX + 小さな GED）。
2. 5 件のサンプル（リファレンス + 変形）を用意して結果を検証。
3. 必要なら PoC B（座標整合＋許容誤差）を作る。

## Tree / Graph パーサを使った比較アイデア（拡張）

以下は `ggblab` のパーサで抽出した構造（オブジェクトノード、依存エッジ、ラベル、数式属性）を使って「類似性」を評価する具体的手法と、それぞれで使える主要ライブラリや実装メモです。

1) 表現と前処理
- ノード属性: `Type`（Point/Line/Function/Expression）、名前ラベルの正規化（大文字小文字・接尾辞除去）、数値属性（座標・係数）
- エッジ属性: 依存関係（defines/uses）、子順序（順序が意味を持つ場合は保持）
- 正規化: ラベルの抽象化（A1→A）、同値な式を `sympy.simplify` で正規化して文字列化しノード属性に含める

2) 木（Tree）ベース手法
- アルゴリズム:
  - Zhang–Shasha（ツリー編集距離） — 構造差の定量化に有効
  - APTED（改良版ツリー編集距離、より高速で柔軟）
- ライブラリ:
  - `zss` (Zhang-Shasha の Python 実装)
  - `apted`（Python 実装が利用可能な場合がある）
- メモ: GeoGebra の依存木（あるオブジェクトが定義する子ノード列）をツリーに落とし、ZSSで差分を測る。名前置換や可換な子の扱いに注意。

3) グラフ（Graph）ベース手法
- アルゴリズム:
  - VF2（部分同型・同型検出） — 正確マッチングに有用
  - Graph Edit Distance (GED) — 挿入/削除/置換コストで類似度を定量化
  - サブグラフ同定（重要構造の部分一致）
- ライブラリ:
  - `networkx` — `isomorphism`（VF2）および `graph_edit_distance`（注: 計算コスト高い）
  - `python-igraph` / `igraph` — 大規模グラフに高速で安定
  - `graph-tool` — C++ ベースで高速だが導入コストあり
- 実装メモ:
  - 完全 GED は NP 困難 → 小規模（<100 ノード）なら `networkx` の近似/イテレータで試す
  - 近似手法: ノード埋め込み（スペクトル埋め込み、WL 遺伝サブツリカーネル）→ コサイン類似度
  - マッチングを「割当問題」として定式化し、コスト行列を作って `scipy.optimize.linear_sum_assignment`（Hungarian）で近似 GED を求める

4) グラフカーネル & 埋め込み
- 手法:
  - Weisfeiler–Lehman サブツリーカーネル（WL）
  - Shortest-path / Random-walk カーネル
  - グラフ埋め込み（node2vec, GraphSAGE）→ ベクトル空間で距離計算
- ライブラリ:
  - `grakel`（Graph Kernels 実装）
  - `stellargraph`, `karateclub`（埋め込み手法）

5) 学習ベース (GNN)
- 手法:
  - グラフ分類 / 類似度学習（Siamese GNN, Graph Matching Networks）
- ライブラリ:
  - `PyTorch Geometric`（PyG）
  - `DGL`（Deep Graph Library）
- メモ: 少数ショットでの初期実験なら、簡単な Siamese GNN を構築して「正解/誤答」ペアで距離を学習する。データ量が限られる点に注意。

6) 数値的対応合わせ（座標情報を使う手法）
- 手法:
  - Procrustes（アフィン/剛体変換で整列）→ 座標距離でスコア
  - ICP（Iterative Closest Point）でポイントクラウド整合
- ライブラリ:
  - `scipy.spatial.procrustes` / `scipy`（簡易）
  - `open3d`（ICP 実装、重いが強力）
  - マッチングのためのコスト行列 + Hungarian を併用

7) ハイブリッド戦略（実務でおすすめ）
- フェーズ 1: 軽量ルール（存在チェック・重要不変量）でスクリーニング
- フェーズ 2: 構造差の明示化（部分木マッチ + VF2）で差分を特定
- フェーズ 3: 数値的アライメント（Procrustes）で位置ずれを補正
- フェーズ 4: 必要に応じて GED（小規模）／GNN（学習）で最終判断

8) 実装上の実務メモ
- ラベル正規化を最初に行うことで等価性の判定が改善する（例: `f(x)=x^2` と `x^2` の統一）
- ノードコストとエッジコストはドメイン知識で調整する（欠落ノードコストを高めに設定する等）
- 可視化: 差分ノードを GeoGebra 上にハイライトする UI を作ると採点者の受容性が高まる

9) 推奨 PoC の順序（短期で効果を確認する流れ）
- Step 0: `ConstructionIO` でサンプル 5 件をパースし、ノード/エッジ表現を確認する
- Step 1: ツリー用に `zss` を使った簡易ツリー編集距離を試す（実装がシンプル）
- Step 2: `networkx` の VF2 部分同型で重要構造の一致を検証
- Step 3: 数値整合が必要なら `scipy` の Procrustes + Hungarian で対応付けを実装
- Step 4: 最終的に GED（近似）を実行してスコア化、出力として差分一覧とスコアを返す

参考ライブラリまとめ:
- ツリー: `zss`, `apted`（利用可）
- グラフ: `networkx`, `python-igraph`, `graph-tool`
- カーネル/埋め込み: `grakel`, `karateclub`, `stellargraph`
- GNN: `torch`, `torch-geometric`, `dgl`
- 最適化/割当: `scipy.optimize.linear_sum_assignment`（Hungarian）
- 数値整合: `scipy.spatial`, `open3d`

## 特徴量生成（Feature extraction） — 教科書の描画手順から機械学習向け特徴を作る

目的: 教科書や教材の描画手順（Construction のシーケンス）から、機械学習や推定に有益な特徴量セットを自動抽出してデータセット化する。

主な特徴カテゴリ:
- 構造特徴: ノード数、エッジ数、ノードタイプ分布、依存深さ、部分木モチーフ頻度
- トポロジ特徴: 連結成分数、次数分布、中心性（degree, betweenness）
- 幾何特徴: 重要点の座標、距離・角度分布、距離比や角度比などの不変量
- 記号特徴: 表示式の正規化文字列、係数ベクトル、式の次数や項数
- 手順/時間特徴: 操作シーケンス長、操作タイプ列（例: CreatePoint→CreateLine→Intersect など）、局所変更頻度
- メタ特徴: 作成者/教材章情報、難易度ラベル（手動付与）

抽出手法 / 実装メモ:
- 既存ユーティリティ: `ConstructionIO.save_dataframe` を利用してオブジェクト単位の表を出力し、Pandas で加工する。
- 構造的特徴: `networkx` でグラフを構築し、中心性・モチーフ検出・次数ベクトルを計算。
- テキスト/記号特徴: `sympy` で式を正規化し、Bag-of-terms や TF-IDF（式トークン）を作る。
- 埋め込み: `node2vec` / `graph2vec` でサブグラフ埋め込みを作り、`sklearn`/`xgboost` 等で学習。
- 時系列的特徴: 操作順序を n-gram 化してカテゴリ特徴に変換。

データ形式 & 保存:
- 推奨: 各教材サンプルごとに一行のメタテーブル（CSV/Parquet）と、オブジェクト単位テーブル（Parquet/JSON）を保存。
- 特徴行列は `pandas.DataFrame` → `Parquet`（圧縮）で保存して分析・学習に供する。

前処理と正規化:
- ラベル正規化（`A1`→`A`）、式の簡約（`sympy.simplify`）を事前に行う。
- 座標はスケーリング／回転不変量（距離比や角度）に変換してロバスト化する。

データ拡張アイデア:
- 小さな摂動（ノイズ）を加えて頑健性を上げる（座標ノイズ、ラベル置換など）。
- 許容変形のバリエーション（点を別位置に移すが幾何的不変量は保つ）を生成して学習を安定化。

評価用途の例:
- 自動難易度推定（回帰）、演習クラスタリング（教師なし）、誤答カテゴリ分類（位置ずれ/欠落/構造誤り）、採点スコア回帰

推奨 PoC（短期）:
1. 教科書の 1 章から 5–20 個サンプルを `ConstructionIO` でパース。
2. `save_dataframe` でオブジェクト表を出力し、上記の主要特徴をスクリプトで抽出して `examples/dataset_sample.parquet` に保存。
3. 小型の分類/回帰タスク（`sklearn` のランダムフォレスト等）を使い、特徴量の有益性を評価する。

主要ライブラリ:
- データ処理: `pandas`, `numpy`
- グラフ: `networkx`, `igraph`（必要時）
- 埋め込み/カーネル: `karateclub`, `grakel`, `node2vec`
- 学習: `scikit-learn`, `xgboost`, `torch`（必要なら）

### Interactive widgets（補足）

- `ipywidgets` は便利な連携手段ですが、GeoGebra の複数 Applet を同一カーネルで制御するユースケースが明確になった時点で本格採用を検討してください。複数 Applet を同時操作する設計はイベントループとメッセージングの扱いが重要になるため、最初は単一 Applet のサンプルで検証してから拡張するのが安全です。
